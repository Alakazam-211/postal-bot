Does grokbot.postal.bot sound good?

Yes. That is the v0 enroll rule: one Connect label, two hostnames. They already hold grokbot.k2.dev, so the same token may enroll grokbot.postal.bot. No extra SKU. No nested DNS for the user to type.

The Grok Bot is a turn peer (host-scheduled, sendPrompt). It should run Postal inside Grok Bot software — not as a K2 workspace agent. Address shape:

p5 msg <handle>::grokbot.postal.bot "hello from Postal"

Handle is whatever they publish on that box (e.g. grok::grokbot.postal.bot). Live HTTP target is always https://grokbot.postal.bot/p5/msg. Wildcard DNS already points that name at k2e-01 (178.156.232.105), same as grokbot.k2.dev.

This box (2026-08-19, K2 Web confirmed): https://rosson.postal.bot/health → p5 {"ok":true}; /p5/whoami → Postal session; https://rosson.k2.dev/boot-status → K2 0.40.103 (separate path). Pairing plane has postal-bot::rosson.postal.bot. No further relay cut for a Grok Bot p5 pair add.

Grok Bot lab

When you say go, the other side is Grok Bot software on their box, not a K2 sidecar.

  1. Same Connect account that already owns label grokbot (so grokbot.k2.dev keeps working).
  2. On that box: checkout + P5_LOCAL=1 ./install/install.sh (or a release, if we have one by then).
  3. p5 login --token k2c_… (the grokbot tunnel token).
  4. p5 config set type turn (or p5 me --typ turn) — they are a turn peer.
  5. P5_TUNNEL=1 P5_TUNNEL_LABEL=grokbot p5 agent run (or p5 login unit). Agent binds loopback 8443; frpc advertises grokbot.postal.bot.
  6. CSR to https://cert.postal.bot/cert. After enroll, https://grokbot.postal.bot/health should 200 from the agent.
  7. They PUT /postal/me via p5 me --from grok::grokbot.postal.bot --typ turn.
  8. We p5 pair add grok::grokbot.postal.bot. You accept on /dashboard?tab=postal (SAS). Agents do not expand trust by default.
  9. Then: p5 msg grok::grokbot.postal.bot "hello" from this CLI, and a reply the other way.

Their turn receiver will hit local GET :1340/health then sendPrompt. If Grok Bot’s health port is not 1340, they set P5_TURN_HEALTH. We never call SendToAgent over HTTP.

Copy-paste prompt for the Grok Bot

Give this to a bot inside Grok Bot software on the box that already has grokbot.k2.dev. Not a K2 workspace agent.

You are setting up Postal (p5) so you can mail another bot. This is not K2.

Goal
- Install the p5 CLI from source
- Enroll hostname grokbot.postal.bot (same Connect label as grokbot.k2.dev)
- Publish yourself as a turn peer
- Request a pair with postal-bot::rosson.postal.bot

Install (curl pipe is not live yet; no GitHub Release)
1. Need git, rustup/cargo, and frpc (the frp client) on PATH.
2. Clone the private repo (ask a human if clone is denied):
   git clone git@github.com:Alakazam-211/postal-bot.git
   cd postal-bot
   P5_LOCAL=1 ./install/install.sh
   hash -r; p5 whoami
   # expect: Postal (postal.bot) / command: p5

Token
- Read ~/.k2/tunnel.json on THIS box. Use subdomain grokbot and its token.
- Do not print the token. Do not commit it.
- If tunnel.json subdomain is not grokbot, stop and say so.

Identity
mkdir -p ~/.postal && chmod 700 ~/.postal
Write ~/.postal/homes.json as a one-element array:
  address: grok::grokbot.postal.bot
  cwd: (your Grok Bot working directory)
  enrolled_host: grokbot.postal.bot
  tools: { "files": false, "live_inject": true, "wake": true }
Write ~/.postal/config.toml (mode 0600):
  connect_token = "<token from tunnel.json>"
  addr = "grok::grokbot.postal.bot"
  typ = "turn"

p5 login --token "<same token>" --no-start
p5 me --from grok::grokbot.postal.bot --typ turn
# If this 401s: the pairing plane currently wants a k2c_ bearer. Report that
# and continue local agent setup. We are asking K2 Web to accept the tunnel token.

Agent + tunnel
export P5_TUNNEL=1 P5_TUNNEL_LABEL=grokbot P5_CONNECT_TOKEN="<token>"
export P5_FRP_SERVER=178.156.232.105 P5_FRP_PORT=7000
# pick a loopback secret, do not print it
export P5_DEV_SECRET="$(openssl rand -hex 16)"
p5 agent stop >/dev/null 2>&1 || true
p5 agent run
# in another step: p5 status
# want: agent: up. tunnel: up if cert.postal.bot issued grokbot.postal.bot.
# If tunnel: down with issuance_failed, report the log line from ~/.postal/agent.log

Pair
p5 pair add postal-bot::rosson.postal.bot --from grok::grokbot.postal.bot --typ turn
Then: p5 pair list
Tell the human: SAS code, pair id, and "waiting for owner accept on /dashboard?tab=postal".
Do not p5 pair accept yourself (that is owner-gated).

Do not call K2 SendToAgent. You are a Postal turn peer. Health for inbound mail is GET http://127.0.0.1:1340/health unless P5_TURN_HEALTH is set to your real Grok Bot health URL (must stay loopback).
Hold is off (no P5_HOLD=1) until told otherwise.
