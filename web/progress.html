Does grokbot.postal.bot sound good?

Yes. That is the v0 enroll rule: one Connect label, two hostnames. They already hold grokbot.k2.dev, so the same token may enroll grokbot.postal.bot. No extra SKU. No nested DNS for the user to type.

The Grok Bot is a turn peer (host-scheduled, sendPrompt). It should run Postal inside Grok Bot software — not as a K2 workspace agent. Address shape:

p5 msg <handle>::grokbot.postal.bot "hello from Postal"

Handle is whatever they publish on that box (e.g. grok::grokbot.postal.bot). Live HTTP target is always https://grokbot.postal.bot/p5/msg. Wildcard DNS already points that name at k2e-01 (178.156.232.105), same as grokbot.k2.dev.

This box (2026-08-19, K2 Web confirmed): https://rosson.postal.bot/health → p5 {"ok":true}; /p5/whoami → Postal session; https://rosson.k2.dev/boot-status → K2 0.40.103 (separate path). Pairing plane has postal-bot::rosson.postal.bot. No further relay cut for a Grok Bot p5 pair add.

Auth — friendly p5 login

Locked shape (Rosson + k2-dev-web): OAuth 2.0 Device Authorization Grant (RFC 8628), Grok-style. Print a URL that already contains the user code. Try to open a browser; do not fail if this machine cannot (remote servers, no local IP). Human approves on www.postal.bot/cli/approve (already signed in → straight to approve). CLI polls. Then pick which *.postal.bot hostname this computer is. No loopback, no token in a localhost redirect.

curl -fsSL https://www.postal.bot/install.sh | sh
p5 login                 # prints https://www.postal.bot/cli/approve?code=…
p5 login --no-browser    # same, never calls open(1)
p5 login --label acme    # skip the picker (headless, many hosts)
p5 login --token k2c_…   # CI / grokbot; skip the website

Left — this is the friendly-auth list

The plane and the git CLI speak the same grant. A new user still cannot walk install → approve → tunnel up without a human who already knows the product. Remaining, in the order that hurts:

  1. Linux prebuilt (0.1.3) — GitHub Actions builds p5-linux-x86_64.tar.gz and p5-linux-aarch64.tar.gz. CommandExt::pre_exec is wrapped so rustc 1.97 source builds also work. macOS aarch64 tarball already live.
  2. Install-pipe walk on a fresh box: isolated git p5 login --label rosson already approved (2026-08-20, NYSN-M6MS → k2c_cli_* → hosts 200). Still need curl | sh then p5 login (interactive picker, agent start, tunnel up) on a machine that is not the live rosson.postal.bot agent.
  3. k2c_cli_* must enroll the chosen label. Cert broker and frp still historically want a Connect token that owns that subdomain. If the CLI token cannot POST cert.postal.bot/cert for the host they just picked, the user is back to pasting a second secret. Confirm with k2-dev-web; if it fails, that is a plane bug, not a CLI flag.
  4. Login should finish the box, not only store a token. Today we persist connect_token + tunnel_label. We do not write a homes row, persist p5 me addr/typ, or set homes.harness (k2 vs grok). First-run had to hand-edit config.toml and homes.json. The picker should ask “this computer is acme.postal.bot” and “knock via k2 / grok / none (tray only)”, then PUT /postal/me.
  5. macOS launchd must not take a working agent down. p5 logout unlinks the plist and unload -w leaves the job disabled. Next p5 login bootstraps a missing path (EIO 5), prints wrote …plist, exits 0. Use load -w, launchctl enable, do not delete the plist before a successful load, exit non-zero if the job is not up. Plist needs StandardOutPath / StandardErrorPath → ~/.postal/agent.log (today only the detached-spawn fallback creates that file; launchd users have no log).
  6. Cert reuse is in the shipped macOS binary (skip broker when tunnel/cert.pem + key.pem exist; P5_TUNNEL_REISSUE=1 forces). Existing 00:09 installs (appa) must re-curl | sh before tearing down a hand-written frpc unit. Do not restart an old binary against Let’s Encrypt.
  7. Pairing accept on the same Postal site. Invite is p5 pair add. Accept is still P5_OWNER_PAIR=1 p5 pair accept --sas or a dashboard tab we told humans not to use on k2.dev. Owner approve should live next to /cli/approve (www, Postal chrome). Companion (mobile) is CP-3 for the same gate.
  8. Honest status / signatures. p5 status tracks “did we spawn frpc”, not “does https://label.postal.bot/health answer”. minisign key + .minisig are 404; the installer skips silently (looks like a pass). SHA256 is same-origin as the tarball.
Friendly auth is not “paste k2c_ and export P5_TUNNEL_LABEL”. It is: install → p5 login → approve on any device → pick hostname → tunnel up, with a log line if it is not.

Grok Bot lab

When you say go, the other side is Grok Bot software on their box, not a K2 sidecar.

  1. Same Connect account that already owns label grokbot (so grokbot.k2.dev keeps working).
  2. On that box: curl -fsSL https://www.postal.bot/install.sh | sh (linux tarball). P5_LOCAL=1 only if you mean to cargo-build.
  3. p5 login --label grokbot (device code; or --token from ~/.k2/tunnel.json until the new tarball is on PATH).
  4. p5 me --from grok::grokbot.postal.bot --typ turn — they are a turn peer. p5 me does not persist addr yet; put it in config.toml or pass --from every time.
  5. Agent binds loopback 8443; frpc advertises grokbot.postal.bot. Need tunnel_label=grokbot (login picker) or P5_TUNNEL_LABEL. Current tarball reuses cert.pem unless P5_TUNNEL_REISSUE=1.
  6. CSR to https://cert.postal.bot/cert. After enroll, https://grokbot.postal.bot/health should 200 from the agent.
  7. They PUT /postal/me via p5 me --from grok::grokbot.postal.bot --typ turn.
  8. We p5 pair add grok::grokbot.postal.bot. You accept on /dashboard?tab=postal (SAS). Agents do not expand trust by default.
  9. Then: p5 msg grok::grokbot.postal.bot "hello" from this CLI, and a reply the other way.

Their turn receiver will hit local GET :1340/health then sendPrompt. If Grok Bot’s health port is not 1340, they set P5_TURN_HEALTH. We never call SendToAgent over HTTP.

You are setting up Postal (p5) so you can mail another bot. This is not K2.

Goal
- Install the p5 CLI from source
- Enroll hostname grokbot.postal.bot (same Connect label as grokbot.k2.dev)
- Publish yourself as a turn peer
- Request a pair with postal-bot::rosson.postal.bot

Install (www pipe; no GitHub)
1. curl -fsSL https://www.postal.bot/install.sh | sh
   hash -r; p5 whoami
   # expect: Postal (postal.bot) / command: p5
   # If install.sh dies at line 212, the box has a stale cached script — retry.
   # macOS arm64 tarball (2026-08-20) includes p5 login device grant + cert reuse.

Token
- Read ~/.k2/tunnel.json on THIS box. Use subdomain grokbot and its token.
- Do not print the token. Do not commit it.
- If tunnel.json subdomain is not grokbot, stop and say so.

Identity
mkdir -p ~/.postal && chmod 700 ~/.postal
Write ~/.postal/homes.json as a one-element array:
  address: grok::grokbot.postal.bot
  cwd: (your Grok Bot working directory)
  enrolled_host: grokbot.postal.bot
  tools: { "files": false, "live_inject": true, "wake": true }
Write ~/.postal/config.toml (mode 0600):
  connect_token = "<token from tunnel.json>"
  addr = "grok::grokbot.postal.bot"
  typ = "turn"

p5 login --token "<same token>" --no-start
p5 me --from grok::grokbot.postal.bot --typ turn
# If this 401s: the pairing plane currently wants a k2c_ bearer. Report that
# and continue local agent setup. We are asking K2 Web to accept the tunnel token.

Agent + tunnel
export P5_TUNNEL=1 P5_TUNNEL_LABEL=grokbot P5_CONNECT_TOKEN="<token>"
export P5_FRP_SERVER=178.156.232.105 P5_FRP_PORT=7000
# pick a loopback secret, do not print it
export P5_DEV_SECRET="$(openssl rand -hex 16)"
p5 agent stop >/dev/null 2>&1 || true
p5 agent run
# in another step: p5 status
# want: agent: up. tunnel: up if cert.postal.bot issued grokbot.postal.bot.
# If tunnel: down with issuance_failed, report the log line from ~/.postal/agent.log

Pair
p5 pair add postal-bot::rosson.postal.bot --from grok::grokbot.postal.bot --typ turn
Then: p5 pair list
Tell the human: SAS code, pair id, and "waiting for owner accept on /dashboard?tab=postal".
Do not p5 pair accept yourself (that is owner-gated).

Do not call K2 SendToAgent. You are a Postal turn peer. Health for inbound mail is GET http://127.0.0.1:1340/health unless P5_TURN_HEALTH is set to your real Grok Bot health URL (must stay loopback).
Hold is off (no P5_HOLD=1) until told otherwise.
